# Lo-fi 房间电台

> 推门进来就好，不用敲门。

一间只在深夜营业的个人小房间：旧唱片机、一只不太理人的猫、写到一半的日记本，
还有一个会偷偷回话的树洞抽屉。这里不是求职网站，就是我的个人空间。

---

## 一、技术栈

| 领域 | 选型 | 说明 |
| --- | --- | --- |
| 框架 | **Next.js 14.2（App Router）** | 服务端渲染 + Route Handler，一个项目搞定前后端 |
| 语言 | **TypeScript 5（strict）** | 全量类型，数据库类型手写在 `src/types/database.ts` |
| 样式 | **Tailwind CSS 3.4 + shadcn/ui 风格组件** | 色板集中在 `tailwind.config.ts` |
| 动效 | **Framer Motion 11** | 轻量、尊重 `prefers-reduced-motion` |
| 后端 | **Supabase**（Postgres + Auth + Storage） | 免费额度足够个人站 |
| 部署 | **Vercel** | 与 Next.js 同源，零配置 |
| 音频 | 原生 `<audio>` + **Media Session API** | 不引入播放器库，锁屏能显示歌名 |
| 状态 | **Zustand** | 播放器、事件、成就三个 store |
| 表单 | **react-hook-form + zod** | 前后端共用同一套 schema |
| 图标 | **lucide-react** | 按需引入，不打包全量 |

**没有用任何付费 API，也没有引入需要付费额度的第三方服务。**

## 二、快速开始

### 0. 环境要求

- Node.js **18.17+**（推荐 20 LTS 或更高）
- 包管理器：`pnpm` 或 `npm` 都行（`node_modules` 是扁平布局，两者通用）

### 1. 初始化命令

如果你是从零开始（本仓库已经建好，可以跳过）：

```bash
# 用官方脚手架生成同样的底座
npx create-next-app@14 lofi-room-radio --typescript --tailwind --eslint --app --src-dir --import-alias "@/*"
cd lofi-room-radio

# 再装上本项目用到的库
npm install framer-motion zustand zod react-hook-form @hookform/resolvers \
  @supabase/supabase-js @supabase/ssr lucide-react class-variance-authority \
  tailwind-merge clsx date-fns sonner \
  @radix-ui/react-slot @radix-ui/react-dialog @radix-ui/react-label \
  @radix-ui/react-tabs @radix-ui/react-switch @radix-ui/react-select \
  @radix-ui/react-dropdown-menu @radix-ui/react-separator @radix-ui/react-slider \
  @radix-ui/react-progress @radix-ui/react-tooltip
npm install -D tailwindcss-animate
```

直接使用本仓库：

```bash
pnpm install     # 或者 npm install
cp .env.example .env.local   # 然后填 Supabase 的三项配置
pnpm dev         # 或者 npm run dev → http://localhost:3000
```

> 什么都不配也能启动：网站会进入「本地演示模式」，用内置示例数据把房间渲染出来，
> 只是不能上传音乐、写日记、投树洞。控制台会提示你还缺哪几个变量。

### 2. 初始化 Supabase 数据库

打开 Supabase 控制台 → **SQL Editor** → 新建查询，**按顺序**依次执行：

| 顺序 | 文件 | 作用 |
| --- | --- | --- |
| 1 | `supabase/migrations/0001_schema.sql` | 建表、索引、触发器、工具函数 |
| 2 | `supabase/migrations/0002_rls.sql` | 打开 RLS 并定义全部策略 |
| 3 | `supabase/migrations/0003_storage.sql` | 建四个存储桶 + 存储策略 + 类型/大小限制 |
| 4 | `supabase/migrations/0004_seed.sql` | 初始化小游戏、成就、站点设置 |

四个脚本都是**幂等**的，重复执行不会删数据。

详细说明见 [`supabase/README.md`](supabase/README.md)。

### 3. 把自己设成站长

1. 启动项目，打开 `/admin/login`，用你的邮箱注册一个账号；
2. 回到 Supabase SQL Editor，执行一次：

```sql
update public.profiles set role = 'admin' where email = '你的邮箱@example.com';
```

3. 在 `.env.local` 里把 `ADMIN_EMAIL` 也填成同一个邮箱（双重保险）。

## 四、环境变量

全部有默认值或可留空，**缺配置不会白屏**，只会降级。

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | ✅ | Supabase 项目地址 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | ✅ | 匿名公钥（会暴露给浏览器，设计如此） |
| `SUPABASE_SERVICE_ROLE_KEY` | ✅ | **只在服务端用**：上传、私密音频签名、审核 |
| `ADMIN_EMAIL` | ✅ | 站长邮箱，与 `profiles.role='admin'` 二选一满足即可 |
| `NEXT_PUBLIC_SITE_NAME` | ⭕ | 站点名，默认「Lo-fi 房间电台」 |
| `NEXT_PUBLIC_SITE_URL` | ⭕ | 正式域名，用于 OG / sitemap |
| `TREEHOLE_IP_SALT` | ⭕ | 给访客 IP 做哈希的盐 |
| `TREEHOLE_MIN_INTERVAL_SECONDS` | ⭕ | 树洞投递最小间隔，默认 60 秒 |
| `TREEHOLE_DAILY_LIMIT` | ⭕ | 树洞每日上限，默认 10 条 |
| `NEXT_PUBLIC_MAX_AUDIO_MB` | ⭕ | 音频大小上限，默认 25 MB |
| `NEXT_PUBLIC_MAX_IMAGE_MB` | ⭕ | 图片大小上限，默认 5 MB |

⚠️ `SUPABASE_SERVICE_ROLE_KEY` 一旦泄漏，等于把整个数据库交出去。
它只出现在 `src/lib/env.server.ts`，那个文件带运行时守卫，被客户端导入会立刻报错。

## 五、数据库设计要点

### 表

| 表 | 用途 |
| --- | --- |
| `profiles` | 用户档案，`role='admin'` 才算站长 |
| `tracks` | 唱片架（音乐元数据 + 公开/私密） |
| `diaries` | 日记（草稿 / 公开 / 私密） |
| `treehole_messages` | 树洞投稿（匿名可写，需审核） |
| `treehole_replies` | 树洞回音 |
| `games` / `game_scores` | 小游戏开关与排行榜 |
| `events` | 房间事件池（权重、冷却、一次性、条件） |
| `achievements` / `user_achievements` | 成就定义与解锁记录 |
| `site_settings` | 站点设置（公开可读，**不放密钥**） |
| `media` | 媒体库索引 |
| `event_logs` | 事件与访问日志（`event_key='page_view'` 用于访问量统计） |

### RLS 三条线

1. **访客（anon）**：只能读公开内容；能写树洞投稿、游戏分数、访问日志。
2. **站长（admin）**：所有表全权。
3. **默认拒绝**：没写策略的操作一律禁止。

两个细节值得说明：

- `treehole_messages` 的插入策略强制 `is_approved = false`，
  访客**无法给自己盖章通过**；审核只能由站长在后台做。
- 树洞限流写在**数据库触发器**里（同 IP 10 分钟 5 条、24 小时 20 条），
  不依赖应用层，绕过前端也刷不动。

### Storage 四个桶

| 桶 | 公开性 | 用途 |
| --- | --- | --- |
| `public-music` | 公开 | 公开音乐，直接给 `publicUrl` |
| `private-music` | 私有 | 私密音乐，服务端签发 `signedUrl`（1 小时） |
| `covers` | 公开 | 封面图 |
| `diary-images` | 私有 | 日记配图，用签名地址展示 |

桶级限制已经写进 SQL：音频 ≤ 25 MB、图片 ≤ 5 MB，且限定 MIME 类型。

## 六、第二批实现了什么

### 1. 房间：18 个可以戳的物件

首页是一间**画出来的房间** —— 全部是手写的 CSS + SVG，没有用任何图片，
所以不涉及版权、能跟着主题色走、也只有几十 KB：

- **家具**：墙面与墙纸、木地板（带透视缝）、踢脚线、窗户（月亮 + 云 + 雨痕 + 窗格 + 窗帘）、
  **床**（挨着窗户，床头板 + 枕头 + 被子 + 床架 + 床腿，占整间屋子的 42% 宽）、
  **床头柜**（带抽屉和拉手，柜上放半杯水和一本扣着的书，纯布景不能点）、
  **沙发**（靠背 + 两个扶手 + 坐垫 + 四条木腿）、
  软木板（钉着纸条 + 图钉）、墙上的画（一片海）、便签墙、地毯（同心花纹 + 流苏）、
  **书桌**（台面分「受光的顶面 + 背光的前沿」两层、围板、上粗下细的腿、腿间横撑）、
  架子（托架 + 墙上投影）、抽屉、台灯、吊在顶上的绿萝、台灯垂下来的电线
- **物件**：唱片机、猫、日记本、热茶、掌机、手机、时钟、收音机、书堆、耳机、植物、雨伞
  —— 12 件全部是手绘 SVG（**不是 emoji**）
- **不可点的大件**：床、沙发、床头柜、书桌、架子、吊在顶上的绿萝、台灯垂下来的电线。
  它们让房间成立，但不抢点击 —— 理由见下面「关于点击区域」
- **灯光是有来源的**：台灯在墙上打出一团暖光、往桌上投出光锥、地板上有一块光斑、
  光柱里还飘着几粒浮尘；关掉灯，这些全部消失，只剩窗外淌进来的一片冷月光。
  光斑和浮尘的坐标都是**相对台灯算的**（`LAMP.x + 偏移`），所以台灯挪位置时
  它们会自动跟着走，不用回来手改六个数字
- 名字**只在鼠标悬停时浮出来**（否则首屏又变成一张 20 多行的标签表）；
  没碰过的东西右上角有一个很小的亮点

> **关于比例**：家具的宽高比是照实物定的。床是 2m 长 : 0.9m 高 ≈ 2.2，
> 所以它是「宽而低」的；早先做成「又高又窄」，看起来就像个立柜而不是床 ——
> 单看「大不大」不够，比例不对照样不像。

> **关于点击区域**：手绘图形在 64×64 的画布里通常留了空白 —— 猫尤其明显，
> 它只占中间那一竖条（左右各留 20% 空）。所以给它和另外两样各补了一圈透明点击区
> （`HIT_PAD`：猫 +20px，热茶和掌机 +10px）。
>
> **床和沙发原本也是可点物件，后来去掉了。** 原因是可点区域太大：
> 猫坐在床上、热茶和掌机摆在沙发上，点那些小东西时经常先打到床和沙发。
> 与其做层级优先级，不如让大件家具老老实实当背景：
> 现在它们由 `Prop`（纯布景壳子，不生成 `button`）渲染，只负责好看。
> 自检里有断言盯着这件事，防止以后不小心又把它们加回 `ROOM_OBJECTS`。
>
> 实测：猫的中心往上下左右各偏 40px 都还是猫；命中测试 26 个可点元素**全部 5/5**，
> 一个「被挡」都没有。

> **关于「每个物件都有话说」**：房间里 18 个可点物件**各自都有专属事件**，
> 不是落到全局文案上。每个的点法都一样：
> **第一次**摸到的一句话（`trigger: 'first'` + `once: true`），
> 之后随机抽两三条，写的是「观察」而不是「事件」——
> 热茶不会突然复活，它只会凉。房间的生动来自细节的累积，
> 不是来自每样东西都会跳。`/api/dev/selftest` 会检查有没有漏掉的物件。

> **为什么不用 emoji**：emoji 是别人设计的彩色字形，混进哑光木色的家具里
> 会像「贴纸贴在画上」，两种画风互相打架，整间屋子立刻显得廉价。
> 另外三条经验写在
> [`room-props.tsx`](src/components/room/room-props.tsx) 开头：
> **要亮**（物件是被台灯照着的，明度必须高于墙）、**要大**（560px 高的房间里至少 60px）、
> **光源方向一致**（统一左上受光）。

**尺寸按容器缩放**：`ART_SIZE` 里的数字是照 1130px 宽的房间调的，
用 [`scalable()`](src/components/room/room-props.tsx) 换算成 `cqw` 之后，
物件会跟着房间等比缩放 —— 窄屏上的布局才不会乱。
（这一条一开始漏了：注释写着「会随容器缩放」，代码里却是死像素。
后果是手机上 92px 的猫占了房间宽度的四分之一，东西全挤在一起，
当时的应对是把全景整个藏掉、窄屏只留文字卡片 —— 于是手机上「房间」就没了。
现在补上了缩放，全景在所有屏幕都显示。）

**窄屏的安排**：手机上（< 640px）房间会加宽到 185% 放在横向滚动容器里，
左右滑着看。按屏幕宽度铺满的话猫只有 29px，房间就是一张看不清的小图；
加宽之后猫约 54px，看得清也点得中。
下面另外保留一份按房间分区排的卡片（墙上 / 架子上 / 桌面上 / 沙发上 / 地上）：
**全景负责「像不像一个房间」，卡片负责「一眼看清有哪些东西」。**
平板（640–1024px）不加宽，按容器铺满时猫就已经有 49px 了。

### 1.1 猫有七个姿势，跟着彩蛋变

猫不是一张固定的图。它会根据**你解锁过的成就（彩蛋）**、房间的灯、还有现在几点换姿势 ——
成就页上写的是字，房间里看到的是**猫的态度变了**。

| 条件 | 姿势 |
| --- | --- |
| 灯是关着的 | **黑里只剩两只眼睛**（竖瞳 + 光晕） |
| 凌晨 0–5 点 | **蜷成一团**睡着（头顶还冒着一个 Z） |
| 解锁「房间的秘密」 | **伸懒腰**（屁股撅起来，前爪往前趴） |
| 解锁「猫的耐心是有限的」（点够 100 次） | **翻肚皮** —— 它认命了 |
| 解锁「外星电台」 | **竖着耳朵**（眼睛瞪大，尾巴僵直立着） |
| 解锁「隐藏抽屉的钥匙」 | **叼来一把钥匙**放在脚边 |
| 以上都没有 | **坐着看你**（默认） |

优先级写在 [`lib/cat.ts`](src/lib/cat.ts) 里，是个纯函数，可以单独测。
有一条特意排在前面：**「钥匙」压过「关灯」** —— 否则一关灯，最深的那个彩蛋
就永远只剩一团黑，没人看得见了。反过来「翻肚皮」这类会让位给关灯。

这七个姿势有 10 条断言在 `/api/dev/selftest` 里（含优先级冲突的两种情形）。

每个物件都支持这些触发方式：

| 触发 | 怎么操作 | 例子 |
| --- | --- | --- |
| 首次互动 | 第一次点它 | 台灯：「咔哒。房间亮了一点。」 |
| 单击 | 点一下 | 猫：「猫翻了个身，把肚皮朝上，又后悔了。」 |
| 双击 | 快速点两下 | 唱片机：换下一首 |
| 长按 | 按住 600ms | 猫：「你摸到了猫。世界暂时安静。」 |
| 连点 | 1.2 秒内连点 | 连点 3 次「别玩开关啦」；7 次「啪。跳闸了。」 |
| 深夜 | 0:00–5:00 点 | 猫：「凌晨的猫最清醒，像值夜班的同事。」 |

键盘也能玩：`Tab` 聚焦、`Enter` / `空格` 是单击、`Shift + Enter` 是长按。

### 2. 事件系统

事件池写在 [`src/lib/events/pool.ts`](src/lib/events/pool.ts)，**内置 60 条**，包含你列出的全部示例
（台灯 4 类、猫 12 条、唱片机 9 条、全局随机 12 条、进出房间 3 条……）。

概率：**隐藏 1% ／ 稀有 5% ／ 普通 70% ／ 剩下 24% 什么都不发生**。
对「点击」类触发，那 24% 会兜底成一条普通事件 —— 你亲手点了，房间总得回你一句；
对随机 / 全局事件则允许真的安静，安静本身也是氛围。

支持权重、冷却、一次性、条件（连点次数 / 连续访问天数 / 小时区间 / 灯的状态 /
点击总次数 / 已解锁成就 / 是否回头客）、深夜限定。

**存储**：已触发事件、冷却、点击次数、连点计数、成就都写在 localStorage，
所以「一辈子只说一次」的文案刷新页面也不会重复出现。

**全局随机事件**每 3–10 分钟抛一条（猫叫、雨势变化、灯泡闪、车灯扫过、手机震动、
黑胶跳针、便签掉落、月亮移动），页面切到后台时会自动跳过。

### 3. 成就

10 个成就，展示在首页的**软木板**上。
未解锁的隐藏成就打码显示。

包含：晚安开灯人、把心事放进抽屉、黑胶旅人、摸鱼大师、常客、房间的秘密、
猫的耐心是有限的、夜猫子、外星电台、隐藏抽屉的钥匙。

### 4. 唱片机与播放器

- 全站唯一的 `<audio>` 放在[根布局](src/app/layout.tsx)里，**切页面音乐不会断**；
- 支持 **Media Session API**：手机锁屏能看到歌名、封面，也能用耳机线控切歌；
- 播放条的进度拖动用一个 `seekToken` 令牌驱动，避免和 `timeupdate` 互相打架；
- 连播 40 分钟自动暂停并提醒休息；
- **0:00–5:00 自动把「深夜」标签的歌排到前面**；
- 播放中会随机冒出「这首歌适合凌晨两点」「黑胶爆豆声像雨」这类事件；
- 私密歌曲对访客不可见（RLS 兜底），站长登录后由
  [`/api/music/signed-urls`](src/app/api/music/signed-urls/route.ts) 签发 1 小时的临时地址。

**演示音频**：还没上传歌的时候，架子上会有三段标着「演示」的音频 ——
它们由 [`scripts/generate-demo-audio.py`](scripts/generate-demo-audio.py) 程序合成，
不涉及任何版权，你上传第一首歌之后就会自动消失。

### 5. 深夜抽屉（树洞）

- **匿名投递**，不用登录、不用邮箱，支持昵称 / 内容 / 心情 / 可见范围；
- 可见范围三档：可以贴到墙上（审核后公开）/ 只给房东看 / 私密保存；
- 投递走 [`/api/treehole`](src/app/api/treehole/route.ts)：服务端算 IP 哈希、扫敏感词、
  过蜜罐字段和垃圾内容判断，最后交给数据库触发器限流
  （同 IP **10 分钟 5 条、24 小时 20 条**）；
- 命中敏感词**只打标记不拦截** —— 提到「银行卡」的人可能正在被诈骗，不该被禁言；
- 树洞墙只展示审核通过的内容，可以举报，累计 3 次自动进后台待审。

### 5.5 图文手帐（照片和字写在一起）

入口在**房间里书桌上的那本日记本**上 —— 点它就走 `/journal`（日记本、抽屉、掌机、
唱片机现在都是「门」：点完既弹事件气泡，也会跳过去）。

- 一条手帐 = 若干照片 + 标题 + 正文 + 日期 + 心情 + 天气 + 标签 + 可见性
- 展示成**拍立得**：白边、胶带、轻微歪斜，说明写在照片下面
- **图文混排**：正文里单独一行写 `[[photo:照片id]]`，照片就插在那个位置。
  没被引用的照片会按顺序补在正文后面，所以「传了但忘了插」也不会丢
- 点照片打开**灯箱**，← → 翻，ESC 关；列表只加载缩略图（`loading="lazy"`），点开才取原图
- 手机端单列
- 口令手帐显示成上锁的一页，输对口令才由服务端取回正文

**照片隐私**（这块是认真做的）：

| 环节 | 做法 |
| --- | --- |
| 剥 EXIF | 上传前在浏览器里「解码 → 画到 canvas → 重新编码」。canvas 只保留像素，**GPS 坐标、设备型号、拍摄时间在重编码时全部消失**；转换前先读对方向，竖拍的照片不会躺下 |
| 验证 | 产物会再查一遍有没有 EXIF 标记，**有就拒绝上传** —— 不能只说「我剥了」，要能证明 |
| 压缩 | 长边 2000 / 质量 0.82，手机直出的 4MB 照片通常压到 200–400KB |
| 缩略图 | 同时生成 480px 缩略图，列表只加载它 |
| 桶的选择 | 公开手帐 → `journal-photos`；私密和口令手帐 → `private-journal-photos` |
| 改可见性 | 从 public 改成 private 时，服务端会把文件**真的搬到私有桶**（跨桶只能下载再上传），否则地址早就可能被爬走了 |
| 口令 | bcrypt 哈希存库；正文**根本不进 RLS 的可见范围**，匿名 key 查它得到 0 行 |

**随机事件也打通了**（点房间里的日记本或抽屉会碰到）：

| 事件 | 效果 |
| --- | --- |
| 猫踩到手帐 | 页面上盖一枚爪印 |
| 翻页掉落旧照片 | 一张拍立得从上面掉下来 |
| 照片背面有字 | 浮出一张写着字的纸背（随机一句） |
| 雨夜照片变暗 | 整页照片压暗一段时间后自己恢复 |
| 抽屉里发现旧手帐 | 最旧的那一页被高亮出来 |

## 七、后台能做什么

入口 `/admin/login`。只有站长能进（数据库 `profiles.role = 'admin'`
或环境变量 `ADMIN_EMAIL`，满足其一即可）。

| 页面 | 能做什么 |
| --- | --- |
| 仪表盘 | 今日 / 7 日 / 累计访问、独立访客、树洞待审数、手帐与唱片数量、播放排行、内容池规模、六个导出按钮 |
| 音乐 | 上传音频 + 封面、编辑元数据、公开 / 私密、上移下移、删除、播放次数 |
| 图文手帐 | 新建 / 编辑 / 删除 / 置顶 / 排序；**拖拽批量上传照片**（浏览器里压缩 + 剥 EXIF + 生成缩略图后直传）；Markdown 正文并插入照片；可见性含 **public / private / password** |
| 树洞 | **翻信式审核**：一次摊开一封，通过 / 只通过 / 隐藏 / 改可见范围 / 写回音 / 删除，做完自动翻下一封；← → 翻信、A 通过、H 隐藏、R 回音；底部有「这一叠」索引可跳转 |
| 事件池 | 增删改，权重 / 冷却 / 一次性 / 条件 / 启用，一键导入内置的 60 条 |
| 成就 | 名称、描述、图标、是否隐藏、排序，补全内置成就 |
| 小游戏 | 开关，查看与清理排行榜 |
| 媒体库 | 六个桶的文件浏览、体积统计、删除、扫描补全记录 |
| 站点设置 | 房间名、标语、关于、天气、公告、游戏厅开关、树洞说明 / 敏感词、版权提醒、社交链接、背景音 |

几个实现上的选择值得说明：

- **写操作全部是 Server Action，而且每一个都先过 `guardAdmin()`。**
  Server Action 是可以被直接 POST 的端点，只在 layout 里做页面级鉴权拦不住直接调用。
- **文件直传 Storage，不经过 Vercel。** Vercel 的 Serverless 函数有 4.5MB 的请求体上限，
  25MB 的音频走服务器中转必然失败。文件由浏览器拿着站长的登录态直接传给 Supabase，
  能不能写进桶里由 Storage 的 RLS 决定。
- **后台统计收敛成一个 RPC**（`admin_overview`）。「去重会话数」这种事在 Supabase JS
  客户端根本做不到，与其查十几次不如让数据库一次算完。
- **树洞审核做成「翻信」**：一次只摊开一封，信纸是真的米色纸（复用 `globals.css` 里的
  `.paper`），做完决定自动翻到下一封 —— 因为「同一档筛选里，刚处理完的那封会消失，
  同一个下标自然就指向了下一封」。不做无限滚动列表，是因为审核需要停下来：
  滑得越顺看得越快，而这里躺着的是别人的心事。同时给了键盘快捷键
  （← → 翻信 / A 通过 / H 隐藏 / R 回音）和底部「这一叠」索引，快慢都能用。

### 两个只在开发环境可用的自查工具（生产环境返回 404）

**1. 事件系统自测** —— `http://localhost:3000/api/dev/selftest`

把事件池的规则跑一遍断言：首次触发、连点优先级、深夜限定、连续访问、
冷却、一次性、稀有度概率分布。当前 **32 / 32 通过**。
改完事件池跑一下，比手动点半天靠谱。

**2. 后台组件预览** —— `http://localhost:3000/dev/preview/journal`

用假数据把每个后台管理组件单独渲染一遍（diary / music / treehole / events /
achievements / games / media / settings）。因为后台页面没配数据库时会直接显示
「还没连上数据库」，配了又需要真的登录 —— 这个页面解决「改完样式没法看」的问题，
同时也是一次「组件不会崩」的冒烟测试。

**3. 截图 + 溢出体检** —— `node scripts/screenshot.mjs 390 880 http://localhost:3000/ .shots/m.png`

用 Chrome DevTools Protocol 精确锁死视口截图，并顺手量一遍 `scrollWidth`，
告诉你有没有真的横向溢出、是哪个元素溢出的。

**4. 命中测试** —— `node scripts/hittest.mjs`

把房间里每个可点物件的中心坐标拿出来，用 `document.elementFromPoint()` 问浏览器
「这个位置最上面的是谁」。

> 截图能看出「好不好看」，但**看不出「点不到」**。被后面画的东西盖住、
> 被浮层挡住、`pointer-events` 被关掉 —— 这些只有命中测试能查出来。
> 这个工具就是这么抓到那个 bug 的：**事件气泡整张卡片是 `pointer-events-auto`**，
> 而它正好浮在房间中下部（猫、地毯、床、雨伞都在那一带），
> 于是「点一下东西 → 冒出一条气泡 → 气泡把底下的东西全挡住」——
> 自己把自己锁死。现在气泡卡片放行鼠标，只有关闭按钮收点击。
>
> 两个容易踩的坑（工具里都注释了）：
> 全局 `scroll-behavior: smooth` 会让 `scrollIntoView` 变成动画滚动，
> 必须写 `behavior: 'instant'`；窄屏那套 DOM 在 `lg` 以上是 `display:none`，
> 不过滤掉会报一堆假的「尺寸为 0」。

**5. 点击测试** —— `node scripts/clicktest.mjs 猫 3`

派发**真实鼠标事件**（不是 `element.click()`）点某个物件，然后看事件气泡有没有冒出来。
「能命中」和「有反应」是两件事 —— 事件可能在冷却里、被 `once` 吃掉了、
或者引擎判定成静默。`CLICK_MODE=js` 可以切成直接调 `element.click()`，
用来区分「React 回调没接上」和「鼠标事件没送到」。
（真实鼠标事件必须给 `buttons` 字段，否则浏览器不把它当一次按压，不会合成 click。）

> 为什么不直接 `chrome --screenshot`：headless 的 `--window-size` 和实际布局视口
> 不是一回事（实测能差 90px 以上），截出来的图看着像「右边被切了」，
> 其实只是截少了 —— 用 CDP 的 `Emulation.setDeviceMetricsOverride` 才准。
> 找不到浏览器时可以用 `CHROME_PATH` 环境变量指定。
> 另外 `SHOT_SETTLE_MS` 可以控制截图前等多久（默认 9.5 秒，好让事件气泡先消失）。

## 九、无障碍、隐私与版权

- **无障碍**：全站键盘可达、有跳转到主内容的链接、焦点环清晰；图标默认 `aria-hidden`；
  不锁死页面缩放；`prefers-reduced-motion` 打开时雨滴和所有动效自动降级。
- **隐私**：树洞不存明文 IP，只存加盐哈希，且仅用于限流；
  页面反复提醒不要写真实姓名、电话、住址这些能定位到本人的信息。
- **版权**：只上传自己创作、免版权或已获授权的音乐；
  页脚和音乐页都有版权提醒。
- **性能**：图标按需引入；雨景是纯 CSS（无 canvas、无定时器）；
  首屏只加载当前路由需要的代码；图片走 `next/image` 并限定远程域名。

## 十一、常见问题

**Q：`npm install` 时提示 `Unknown project config "node-linker"`？**
A：这是 npm 不认识 `.npmrc` 里那条 pnpm 专用配置，只是提示，不影响安装。
留着它是因为 pnpm 会用它生成扁平的 `node_modules`，让两种包管理器可以混用。

**Q：启动后页面是空的 / 控制台提示「本地演示模式」？**
A：正常。`.env.local` 里的 Supabase 三项还没填。填好后重启 `npm run dev` 即可。
演示模式下唱片架上有三段程序合成的示例音频，可以真的播放。

**Q：`/admin` 一直被踢回登录页？**
A：先去 `/admin/login` 注册账号，再到 Supabase SQL Editor 执行一次提权语句
（`update public.profiles set role='admin' where email='你的邮箱'`），见第五节。

**Q：后台页面显示「还没连上数据库」？**
A：说明 `isSupabaseConfigured` 是 false。检查 `.env.local` 里的
`NEXT_PUBLIC_SUPABASE_URL` 与 `NEXT_PUBLIC_SUPABASE_ANON_KEY`，改完要**重启**开发服务器。

**Q：后台仪表盘报「统计函数还没建好」？**
A：`0005_admin_stats.sql` 没执行。回 Supabase SQL Editor 跑一遍。

**Q：日志里出现 `spawn EPERM` 或构建 worker 启动失败？**
A：说明当前环境不允许 fork 子进程（容器、CI 沙箱常见）。
用 `NEXT_USE_WORKER_THREADS=1 npm run build` 把构建 worker 换成线程试试。

**Q：为什么标题字体不是 Space Mono？**
A：默认走系统等宽字体，为了离线也能构建、中文不缺字。
想换看 [`docs/字体与素材.md`](docs/字体与素材.md)。
